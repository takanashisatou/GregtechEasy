# AI-движок интернационализации перевода (`opencode_translate.py`)

Проект GTE реализует промышленную систему многоязычной интернационализации, управляемую единым скриптом, охватывающую три области: ассеты модов, книги заданий FTB и документацию Markdown.

---

## 🔒 Пять железных правил перевода

Работа по переводу в этом проекте подчиняется следующим **5 незыблемым правилам**:

1. **Единый скрипт**: Все переводы выполняются исключительно с помощью `scripts/opencode_translate.py`, подключённого к модели `deepseek-v4-flash` от OpenCode Zen. Запрещено вводить второй скрипт перевода или вручную собирать вызовы API.
2. **Облачное выполнение**: Все полные переводы должны выполняться в GitHub Actions CI (`translate.yml` / `docs-deploy.yml` / `sync-build.yml`). Категорически запрещено выполнять массовые переводы локально вручную.
3. **Единственное размещение**: Весь сайт развёртывается единообразно на `https://takanashisatou.github.io/GregtechEasy/` (ветка `gh-pages`). Не создавать второй сайт документации и не выполнять повторное развёртывание.
4. **Правила для английского языка**:
   - Система документации (`docs/en/`): Английский язык должен полностью переводиться ИИ из `docs/zh/`, ручное перезаписывание запрещено;
   - Мод-проект: Только `en_us.json` для `gtecore` поддерживается вручную, скрипт имеет встроенную защиту и никогда не перезаписывает его машинным переводом.
5. **Глубокая локализация**: Навигационное меню (`nav_translations`), текст диаграмм Mermaid, комментарии в коде и метки таблиц должны быть локализованы на 100% на соответствующий язык.

---

## 🤖 Архитектура движка перевода

Традиционная локализация сообщества полагалась на ручное обслуживание сложных JSON и SNBT текстов, что приводило к задержкам обновлений и частым ошибкам.

AI-движок перевода GTE через стандартизированный OpenAI-совместимый API реализует **автоматическое инкрементальное извлечение, выравнивание терминов и параллельный перевод** для книг заданий FTB Quests и языковых файлов основных модов:

```mermaid
graph TD
    A[Сканирование FTB Quests snbt и Lang json] --> B[Извлечение непереведённых записей]
    B --> C[Чтение локального кэша .translation_cache.json]
    C --> D{Есть ли новые или изменённые записи?}
    D -- Нет --> E[Непосредственная синхронизация записи в целевой языковой файл]
    D -- Да --> F[Сборка Prompt с ограничениями по промышленным терминам GregTech]
    F --> G["Приоритетный вызов OpenCode deepseek-v4-flash<br/>Failover: DeepSeek / Gemini / Qwen / Kimi / GLM"]
    G --> H[Проверка и обновление локального кэша]
    H --> I[Запись обратно в zh_cn.json / en_us.json / ftbquests/lang/]
```

Скрипт автоматически выбирает первый доступный API-ключ по следующему приоритету, без необходимости указывать провайдера вручную:

| **1 (предпочтительно)** | **OpenCode Zen** | `OPENCODE_API_KEY` | `OPENCODE_BASE_URL` | **`deepseek-v4-flash`** |
| 2 | DeepSeek | `DEEPSEEK_API_KEY` | `DEEPSEEK_BASE_URL` | `deepseek-chat` |
| 3 | Google Gemini | `GEMINI_API_KEY` | `GEMINI_BASE_URL` | `gemini-3.6-flash` |
| 4 | Qwen (DashScope) | `DASHSCOPE_API_KEY` | `DASHSCOPE_BASE_URL` | `qwen-plus` |
| 5 | Moonshot | `MOONSHOT_API_KEY` | `MOONSHOT_BASE_URL` | `moonshot-v1-8k` |
| 6 | Zhipu GLM | `ZHIPU_API_KEY` | `ZHIPU_BASE_URL` | `glm-4-flash` |
| 7 | OpenAI | `OPENAI_API_KEY` | `OPENAI_BASE_URL` | `gpt-4o-mini` |
| 8 | Универсальный агрегатор-прокси | `LLM_API_KEY` | `LLM_BASE_URL` | `LLM_MODEL` (пользовательский) |

> **Примечание**: Для полной работы CI достаточно настроить `OPENCODE_API_KEY` в GitHub Secrets. Остальные — резервные Failover.

## 🎯 Промышленные принципы ограничения Prompt

При вызове API для перевода система имеет встроенные строгие правила терминологии Minecraft и GregTech:

1. **Абсолютное сохранение форматирования**: Полностью сохраняются нативные коды форматирования цвета Minecraft (например, `§a`, `§c`, `§6`) и плейсхолдеры (`%s`, `%d`, `{0}`).
2. **Единообразие научно-технических терминов**: Строго фиксируется перевод технических терминов (например, `UHV`, `EU/t`, `Amps`, `Voltage`, `Overclock`, `Subtick` и т.д.).
3. **Хэш-инкрементальный кэш**: Все переведённые записи автоматически сохраняются в `.translation_cache.json`, сетевые запросы отправляются только для новых или изменённых текстов, что значительно экономит токены и время CI.
4. **Локализация текста диаграмм Mermaid**: Метки узлов диаграмм (например, `A[метка]`) переводятся на целевой язык, а синтаксические ключевые слова, такие как `graph TD`, `-->`, `subgraph`, остаются неизменными.
5. **Комментарии в коде и метки таблиц**: Комментарии внутри блоков кода (`//` / `#`) и заголовки столбцов таблиц полностью локализуются.

## 💻 Способы запуска CI (облачное выполнение, правило 2)

| Сценарий | Рабочий процесс | Способ запуска |
| :--- | :--- | :--- |
| Автоматическая полная сборка + перевод после пуша кода | `sync-build.yml` | Автоматически при пуше в `main`/`master` |
| Автоматический перевод + развёртывание после изменений документации | `docs-deploy.yml` | Срабатывает при изменении `docs/` или `mkdocs.yml` |
| Ручной полный перевод ассетов мода | `translate.yml` | Ручной запуск на странице Actions, выбор провайдера и языка |
| Ручной полный перевод документации | `translate.yml` | Установка флажка `translate_docs` во входных данных |

> [!CAUTION]
> Запрещается запускать `python scripts/opencode_translate.py` локально вручную для массового полного перевода. Локальный запуск допускается только для отладки отдельных файлов или проверки доступности API-ключа.
